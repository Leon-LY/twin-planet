## 一、产品经理论证（3人）

### 产品经理 A — 资深母婴产品总监

**评分**: ⭐⭐⭐ (3/5)

**核心判断**: "产品骨架是对的，但肉还没长全。"

| 发现 | 严重度 | 位置 |
|------|:--:|------|
| 贴纸系统只在 4 个页面接入，sprout 接入但参数有问题 | 🟠 | sprout:123 |
| 奶奶模式 `font-large` class 完全没有 CSS 效果 | 🔴 | App.vue + index:171 |
| 隐私政策声称"7天自动删除录音"但实际没有 TTL | 🟠 | privacy:11 vs handover:87 |
| 角色 `other` 在注册时可选但首页无法切换回 | 🟠 | family:80 vs index:321 |
| 记录页 `quickLog` 和 `startTimer` 无错误处理，动画播了但数据可能没存 | 🟠 | record:127 |

**产品经理 A 的建议**:
1. 贴纸系统必须接入所有产生用户行为的页面（contribution, milestones, school 都缺）
2. 奶奶模式需要端到端测试——大字体是否真的在每个页面生效
3. 隐私政策必须和实际代码行为一致，否则微信审核直接拒绝
4. 首次使用引导缺失——新用户不知道贴纸是什么、怎么收集

### 产品经理 B — 微信生态产品专家

**评分**: ⭐⭐⭐ (3/5)

**核心判断**: "微信审核大概率不会通过。"

| 发现问题 | 严重度 |
|------|:--:|
| `requiredPrivateInfos` 声明了 `chooseAddress` 和 `getLocation` 但从未使用 | 🔴 |
| manifest 有大量无关 Android 权限（READ_LOGS, MOUNT_UNMOUNT_FILESYSTEMS 等） | 🟠 |

| `es6: true` 导致低端 Android 手机（爷爷奶奶常用）无法运行 | 🟡 |

**产品经理 B 的建议**:
1. 立即删除 `requiredPrivateInfos` 中不用的权限声明
2. 登录页增加"登录即表示同意《用户协议》和《隐私政策》"文字 + 勾选
3. 考虑将 `es6` 设为 `false` 或发布时做兼容性测试

### 产品经理 C — 增长与留存专家

**评分**: ⭐⭐ (2/5)

## 四、架构设计论证（3人）

### 架构师 A — 系统架构专家

**评分**: ⭐⭐⭐ (3/5)

**核心判断**: "前端架构是经过思考的——store 依赖无环，persistence 统一。但后端架构问题很大。"

| 问题 | 严重度 |
|------|:--:|
| 3 个不同的 JWT secret fallback 值——token 可能被一个 secret 签发、另一个 secret 验证失败 | 🔴 |
| `twin_groups.baby_ids TEXT[]` 用数组而不是关联表——无法外键约束 | 🟠 |
| 硬编码双胞胎逻辑（`birth_order IN (1,2)`、`baby_a_need/baby_b_need`）——三胞胎无法支持 | 🟡 |
| 没有迁移版本表——schema 无法演进 | 🟠 |
| 没有 ON DELETE CASCADE——删用户会导致孤儿数据 | 🟠 |
| Redis 依赖声明了但从未连接 | 🟢 |
| Zod 依赖声明了但从未使用 | 🟢 |
| `twinGroupId` 在 babies store 和 family store 之间不同步 | 🟠 |

**架构师 A 的建议**:
1. 统一为一个 JWT secret 来源（只用 config.ts 的）
2. `twin_groups` 改为关联表 `twin_group_members(group_id, baby_id, birth_order)`
3. 迁移加版本表 `schema_migrations(version, applied_at)`
4. 所有外键加 `ON DELETE CASCADE`
5. 删除未使用的依赖（redis, zod, bcryptjs）

### 架构师 B — 数据架构专家

**评分**: ⭐⭐⭐ (3/5)

**核心判断**: "前端持久化架构基本合理，但缺少几个关键索引和状态管理。"

| 问题 | 位置 |
|------|------|
| `activeBabyId` 没有持久化——app 重启后用户选择丢失 | babies.ts:32 |
| `activeSession` 没有持久化——app 杀掉后进行中的计时丢失 | guardian.ts:87 |
| `lastSyncAt` 没有持久化——不知道上次同步时间 | stickers.ts:100 |

2. records logs 考虑分页或按月分片存储

4. 所有实体加 `updated_at` 字段
