# 双宝记 · 贴纸收集体系重设计

> 2026-06-18 v2.0 — 从「emoji 字符」到「手绘水彩双狐插画收藏册」
> 替代旧版：21 张 emoji/iconfont 贴纸（无插画、无稀有度、无收集欲望）

---

## 一、问题诊断

### 旧版贴纸的 5 个致命问题

| # | 问题 | 现状 | 后果 |
|---|------|------|------|
| 1 | **无插画资产** | 贴纸 = emoji 字符（☀️👀🦸）+ iconfont CSS 字体图标 | 视觉零吸引力，跟品牌无关 |
| 2 | **无稀有度分层** | 21 张贴纸全部同等价值，"第1次记录"和"连续30天"一样珍贵 | 无追求感，无炫耀感 |
| 3 | **无主题叙事** | 按 `record/streak/sync/milestone/special` 功能分类，不是情感分类 | 像功能清单，不像收藏册 |
| 4 | **与双狐 IP 脱节** | 贴纸里没有任何狐狸元素 | 品牌识别断裂 |
| 5 | **无收集奖励** | 集齐 21 张没有任何额外反馈 | 集满即弃，无复访动力 |

## 二、设计哲学

### 核心理念：每张贴纸是一幅小画，不是一个图标

> **"撕下一张贴纸，就是撕下日记里的一页小插画。"**

双宝记的贴纸不是 Slack emoji，而是**手帐装饰贴纸**——就像你在文具店买的那 种手绘水彩贴纸，贴在手帐本上让日记变好看。

每张贴纸遵循三条铁律：
1. **有角色** — 每张贴纸都出现双狐（Amber 狐 / Terracotta 狐 / Gold 狐）
2. **有场景** — 每张贴纸讲一个微小的双胞胎生活瞬间
3. **有温度** — 手绘水彩质感，看得见笔触和纸张纹理

## 三、稀有度系统

### 4 级稀有度，视觉与情感差异化

| 等级 | 中文名 | 标识 | 边框 | 动效 | 占比 | 获取感 |
|------|--------|------|------|------|------|--------|
| **C** | 日常 | 🌰 橡果 | 虚线边框，无光晕 | 轻微弹出 | 50% | 「嗯，收到了」 |
| **R** | 稀有 | 🌿 嫩叶 | 实线边框 + 淡光晕 | 弹出 + 微闪烁 | 30% | 「还不错」 |
| **E** | 史诗 | 🌟 星辰 | 金色双层边框 + 光晕 | 弹出 + 金色粒子 | 15% | 「太棒了！」 |
| **L** | 传说 | 🦊 狐印 | 虹彩边框 + 强光晕 + 烫金底 | 全屏庆祝弹窗 | 5% | 「截屏发朋友圈！」 |

### 稀有度视觉规范

```
日常 C ── 虚线 2rpx #D4C8B8，无阴影，无光晕
稀有 R ── 实线 2rpx var(--terracotta)，box-shadow 0 0 16rpx rgba(192,133,82,0.2)
史诗 E ── 双层：外金 3rpx var(--gold) + 内实 1rpx var(--amber)，光晕 + 4 颗金色小星粒子
传说 L ── 虹彩渐变边框（amber→gold→terracotta），强光晕 + 烫金底纹 + 全屏彩屑动画
```

## 六、数据结构升级

### 新增 `rarity` 字段 + `collection` 字段

```typescript
export interface Sticker {
  id: string
  /** 手绘插画资产路径（替代 emoji/iconClass） */
  illustration: string
  /** 保留 emoji 作为降级方案 */
  emoji: string
  label: string
  /** 稀有度 */
  rarity: 'common' | 'rare' | 'epic' | 'legendary'
  /** 所属收藏册 */
  collection: 'daynight' | 'growth' | 'twin' | 'milestone' | 'honor' | 'solar' | 'hidden'
  /** 节气贴纸专用：对应节气 key */
  solarTerm?: string
  /** 是否为隐藏贴纸（不在图鉴显示） */
  hidden?: boolean
  category: 'record' | 'milestone' | 'streak' | 'sync' | 'special'
  earnedAt: number
  babyId?: string
}
```

### 收藏册进度

```typescript
export interface CollectionProgress {
  collection: string
  total: number
  earned: number
  completed: boolean
  completedAt?: number
  /** 集齐奖励是否已领取 */
  rewardClaimed?: boolean
}
```

## 七、视觉规范

### 贴纸尺寸

| 用途 | 尺寸 | 说明 |
|------|------|------|
| 首页贴纸条 | 96rpx × 96rpx | StickerStrip 组件 |
| 收集册网格 | 160rpx × 160rpx | 3 列网格 |
| 解锁庆祝弹窗 | 400rpx × 400rpx | 全屏中央 |
| 分享卡片 | 80rpx × 80rpx | 周报贴纸展示 |

### 插画规范

- **风格**：手绘水彩，可见笔触，纸张纹理
- **角色**：双狐（Amber #E07B3E + Terracotta #C08552 + Gold #C8993E）
- **背景**：透明 PNG（收集册用）或暖白 #FEF9F0（展示用）
- **边框**：贴纸感白色描边 + 微投影
- **尺寸**：1024 × 1024 原图，按需缩放

### 未解锁态

未解锁的贴纸在收集册中显示为：
- **轮廓剪影**（黑色 20% 透明度的狐狸轮廓）
- **问号标签**：「???」
- **提示文字**：模糊的获取线索（如「连续记录多天会有惊喜」）

## 九、旧版迁移策略

### 向后兼容

1. **保留 `emoji` 和 `iconClass` 字段** — 作为插画加载失败的降级方案
2. **新增 `illustration` 字段** — 优先级最高，有则用插画，无则降级到 iconClass，再降级到 emoji
3. **保留旧 `category` 字段** — 用于内部逻辑，不影响 UI 展示
4. **`STICKER_RULES` 保留旧触发逻辑** — 只改贴纸元数据（名称、插画、稀有度），不改触发条件

### 迁移步骤

```
Phase 1: 数据结构升级（加 rarity/collection/illustration 字段）
Phase 2: 生成全部 50 张手绘水彩贴纸插画
Phase 3: 更新 STICKER_RULES 元数据
Phase 4: 更新收集册 UI（按收藏册分组 + 稀有度边框）
Phase 5: 实现集齐奖励系统
Phase 6: 实现 24 节气限定逻辑
```
